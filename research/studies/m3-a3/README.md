## 2. 模型与执行方式对照

当前模型为Qwen3-Coder-30B-A3B-Instruct；候选更大编码模型为[Qwen3-Coder-Next](https://huggingface.co/Qwen/Qwen3-Coder-Next)，固定提交a7fbcb5c0e12d62a448eaa0e260346bf5dcc0feb，BF16、80B总参数/3B激活。模型在新能力结果出现前选定，模型能力仍以本轮实测为准。全部权重及tokenizer内容核对固定HF身份，官方ModelScope传输副本逐项对照同一摘要。

标准Agent采用[mini-swe-agent](https://github.com/SWE-agent/mini-swe-agent)固定提交04d809ceab9df28f9adaed044884180159172930（2.4.6），保留官方DefaultAgent、mini.yaml、解析、观察和显式提交。共享适配只接入同一模型传输、实际token记账和Docker工具后端。这个条件估计完整执行方式的组合效果，包括Prompt、工具格式、10k/40k观察截断和终止规则；单个内部机制需要后续单因素对照。

本轮使用Kernel.work的直接Worker入口，额外的完成声明检查未启用；这个设置在付费调用前登记。两个source025条件使用完全相同的入口，标准Agent保留自身的原始完成规则。原生角色范围约束按其独立协议保留。

统一预算：每题2M实际API tokens、100次模型调用、任务执行3600s、工具120s，最大输出8192、上下文262144、1CPU/4GiB。模型请求温度0.7、top_p0.8、top_k20、repetition_penalty1.05、seed20261102；同一vLLM0.20.0、4卡BF16服务、关闭prefix cache。在线推理批处理和数值运算使同一种子仍可能出现输出差异。

原始任务、评分脚本、镜像、隐藏材料隔离和禁网规则均沿用冻结输入。每个补丁经过独立新容器评分及固定原始Harbor评分，两者逐项核对。CPU/RAM从容器内cgroup读取确认。源结果中的自建后端标志保留，单次正式评分的验收由protocol-attestation.json给出。

九份评分均通过原始Harbor/独立结果一致性、原始验证器和真实资源验收；实际执行/捕获最长3101.0s，均在共同3600s范围内。两个source025模型条件的首次完整messages+tools在三题中逐字一致，摘要保存在CAPABILITY-RESULTS.json。实测评分的五个实现文件与公开副本逐字一致；43个冻结内核文件及77个标准Agent源码文件复核一致。

## 3. System Track

147格零模型机制实验：120格容量测量、27格事件测量，另有独立进程恢复与不确定工具操作拒绝重放。

16任务/4槽位、每事件100ms固定工作量下，Single平均1.885s，Eager Delegation0.540s，Super-agent0.542s；后两者均实际同时执行最多4个工作单元。高频后续事件共36个工作单元，订阅将Router固定回复次数从36降至4，工作量、完成数和未读事件逐项核对。

持久上下文在这个事件负载中增长更快，但字符数只是构造上下文的测量结果，真实模型费用需要另行测量。恢复验收覆盖空闲检查点后四个唯一事件、四个工作单元、重复0；不确定的工具副作用仍要求明确核对。

[系统报告](SYSTEM-REPORT.md)提供完整均值、两张图、环境和局限。全部API调用及tokens均为0，逻辑槽位与异步等待负载测量系统调度机制；真实任务成功率由上面的能力对照单独报告。

## 5. 下一步判断

建议将Qwen3-Coder-Next + 冻结source025作为下一轮共同基线候选，保留当前执行内核，不继续针对cachetools修改Prompt。较大模型在两个任务上出现实质代码/契约进展；标准Agent的结果随任务变化，现有样本提供了保留既有内核的实际理由。这个候选仍只有三道任务证据，原生AsynCodeBench上的新模型收益尚未验证。

本轮到此停止新增能力实验。System Track已独立推进，研究状态框架可以发布；M3-B的24题、1/4并发比较继续冻结，待下一阶段统一模型与预算协议后使用原清单推进。

本轮没有扩展24题，没有为Super-agent单独更改Worker，也没有启动新Router算法或模型训练。后续共同基线一旦选定，需要冻结模型与Worker，并在全部架构中使用同一版本。
